# Codebase guide

*[Hrvatska verzija](hr/vodic-kroz-kod.md)*

A map of the Uputko code for teammates and reviewers: where everything lives,
how a request moves through it, and how to change things without breaking the
demo. For *why* it is built this way, see [`architecture.md`](architecture.md);
for the data, see [`data-sources.md`](data-sources.md).

## 2. Pages

All pages are server components that load data on the server; only
interactive parts are client components (`"use client"`).

| URL | File | What it is |
|---|---|---|
| `/` | `src/app/(patient)/page.tsx` | Landing: one main action, "Moji slučajevi", how it works |
| `/profil` | `src/app/(patient)/profil/page.tsx` | Pick a demo persona, see/change chosen doctors; demo box in demo mode |
| `/chat` | `src/app/(patient)/chat/page.tsx` → `ChatScreen` | The intake conversation (redirects to `/profil` if no persona) |
| `/slucaj/[id]` | `src/app/(patient)/slucaj/[id]/page.tsx` → `CaseScreen` | Case page: progress, uputnica, appointment, offers, timeline (live) |
| `/javni-podaci` | `src/app/(patient)/javni-podaci/page.tsx` | Open-data counts, city map, datasets (cached 1 h) |
| `/lijecnik/slucaj/[token]` | `src/app/(doctor)/lijecnik/slucaj/[token]/page.tsx` | Doctor portal (desktop-first), reached by the email link |
| `/ustanova` | `src/app/(institution)/ustanova/page.tsx` | Demo-only hospital panel: free an earlier slot, answer reschedule requests |

Route groups `(patient)`, `(doctor)`, `(institution)` only organise files;
they do not appear in URLs.

## 3. API routes

Every body, query and parameter is validated with **Zod**. Patient routes check
that the demo identity cookie (`uputko_patient`) owns the case, appointment or
notification (`lib/patientAuth.ts`).

| Method · path | File | Purpose |
|---|---|---|
| `POST /api/chat` | `api/chat/route.ts` | One chat turn, streamed as Server-Sent Events (`case`, `ready`, `delta`, `options`, `confirm`, `outcome`, `error`, `done`). Flags: `finish` (Pošalji liječniku), `retry` (answer the last message again) |
| `GET/POST/DELETE /api/session` | `api/session/route.ts` | Which persona am I / pick one / forget it |
| `GET /api/cases/[id]` | `api/cases/[id]/route.ts` | Fresh case data; the case page refetches it on every live ping |
| `GET /api/practitioners?role=&q=` | `api/practitioners/route.ts` | Doctor search for onboarding (open data) |
| `POST /api/profile/doctors` | `api/profile/doctors/route.ts` | Change a chosen doctor |
| `POST /api/doctor/[token]/extract` | `api/doctor/[token]/[action]/route.ts` | Read an uploaded uputnica with Claude; match specialty + hospital |
| `GET /api/doctor/[token]/institutions` | same file | Hospitals near the patient for a specialty |
| `POST /api/doctor/[token]/issue` | same file | Save the referral, book the earliest slot (or the nearest other hospital), notify the patient |
| `POST /api/doctor/[token]/invite` | same file | "Pozovite pacijenta na pregled" instead of an uputnica |
| `GET /api/appointments/[id]/ics` | `api/appointments/[id]/[action]/route.ts` | Calendar file |
| `POST /api/appointments/[id]/(confirm\|cancel\|reschedule)` | same file | Patient actions on the appointment |
| `POST /api/notifications/[id]/(accept\|decline)` | `api/notifications/[id]/[action]/route.ts` | Answer an earlier-slot / reschedule offer |
| `POST /api/institution/(free-earlier\|offer)` | `api/institution/[action]/route.ts` | Demo hospital panel actions |
| `GET /api/referrals/[id]/document` | `api/referrals/[id]/document/route.ts` | The uploaded uputnica, for its patient only |
| `POST /api/demo/reset` | `api/demo/reset/route.ts` | Demo mode only: clear the personas' cases, free their slots |

## 4. One chat message, end to end

What happens when the patient sends "Boli me uho već dva dana":

1. **`ChatScreen`** (`components/chat/ChatScreen.tsx`) adds the bubble, opens
   `POST /api/chat`, and reads the event stream.
2. **`api/chat/route.ts`**: checks the persona cookie, validates the body, rate
   limits (`lib/rateLimit.ts`), finds or creates the case, saves the location
   if given, stores the message.
3. **Safety gate**: `checkRedFlags(message)` (`lib/agent/redFlags.ts`). A hit →
   `escalateEmergency()` (`lib/agent/outcome.ts`) → `outcome` event →
   `EmergencyTakeover`. The model is never called.
4. **Agent turn**: `runAgentTurn()` (`lib/agent/run.ts`) sends the system prompt
   (`lib/agent/prompt.ts`), the patient's context and the history to Claude with
   three tools: `get_my_doctors`, `find_places`, `submit_case_summary`. Text
   streams to the browser as `delta` events; a trailing `OPCIJE: a | b` line
   becomes quick-reply buttons (`lib/agent/options.ts`).
5. **Submit**: when the agent calls `submit_case_summary` before the patient
   said yes, nothing is sent: the route emits `confirm` and the chat shows
   *Da, pošalji* / *Ne, želim nešto dodati* (`lib/agent/confirm.ts`; urgent
   cases skip this). After yes (the button, or a typed "da"), the summary is
   validated (`lib/agent/schemas.ts`) and `submitCase()` (`lib/agent/outcome.ts`)
   runs **deterministic routing** (`lib/agent/routing.ts`): direct (nearest open
   practice) or via the chosen doctor (email + doctor link).
6. **Demo mode** wraps step 4: `demoSafeTurn()` in the same route switches to a
   prepared reply (`lib/demo.ts`) if nothing streams within 8 s.

## 7. Database

Migrations run in filename order. To add one, create the next numbered file,
apply it locally, update `src/lib/db/types.ts`, and push it to the hosted
database after merging (see §11).

| Migration | What it adds |
|---|---|
| `20261105000001_reference_data` | Open-data tables: institutions (PostGIS), specialties, services, hours, practitioners |
| `20261105000002_patient_flow` | Patients, cases, messages, referrals, slots, appointments, notifications, case events; one live appointment per slot |
| `20261105000003_functions_security` | Nearest-place search, open status, synthetic slot generator, Row Level Security, Realtime |
| `20261106000001_doctor_loop_booking` | Doctor tokens, rate limits, all booking and offer functions, patient profile, institution card |
| `20261107000001_open_data_stats` | Counts for `/javni-podaci` |
| `20261107000002_fix_slot_availability` | A slot is available only if no live appointment holds it |
| `20261107000003_demo_reset` | "Počni ispočetka" for demo mode (synthetic patients only) |
| `20261107000004_propose_at_institution` | Book at the nearest other hospital when the chosen one is full |

All state-changing functions are revoked from the public roles: only server
routes (service role) can call them.

## 8. Live updates

`addCaseEvent()` writes a `case_events` row and calls `broadcast()` on
`case:<id>`. `useLiveCase()` (`src/hooks/useLiveCase.ts`) listens on the case
and patient topics and refetches `/api/cases/[id]`, with a 15 s poll as a
safety net. The ping carries no data; the refetch goes through the
authenticated API.

## 9. Data pipeline (`data-pipeline/`)

| File | Step |
|---|---|
| `sources.py` | Every dataset (CKAN package + resource) |
| `fetch.py` | Download through the data.gov.hr CKAN API + OpenStreetMap Overpass → `data/raw/` (+ `manifest.json`) |
| `transform.py` | Clean, normalise, fuzzy-join hospitals, map specialties, dedupe → `data/clean/` |
| `geocode.py` | Missing coordinates via Nominatim (1 req/s), cached in `data/cache/geocode.json`, wrong-town check |
| `load.py` | `data/clean/` + synthetic personas/hours → `supabase/seed.sql` |
| `build.sh` | Offline rebuild from the committed snapshot |
| `tests/test_transform.py` | pytest for the transforms |

Raw and clean snapshots are committed, so `./build.sh` needs no internet.

## 11. Common tasks

**Add or change UI text.** Edit `src/i18n/hr.ts` only; never put strings in
components.

**Add a page or component.** Put it in the matching folder (§2, §6). Every async
part needs loading (skeleton), empty, error and success states,
keyboard access and reduced-motion handling. Base text is 18 px, and the layout
must survive "Veća slova" (21 px). Run `e2e/a11y.spec.ts`.

**Change the emergency rules or the system prompt.** Update
`redFlags.test.ts` (a positive **and** a negative case per rule), run
`pnpm test` and `pnpm eval`, and state the behavioural change in the commit
(CLAUDE.md §3 rule 6).

**Add a persona's prepared demo conversation.** `SCRIPTS` in `src/lib/demo.ts`,
keyed by the persona's name.

**Add a migration.** New numbered file in `supabase/migrations/`, then locally:
`pnpm dlx supabase@3.0.0 db reset` (or apply the file to the running local
database), update `src/lib/db/types.ts`. After merging to `main`:
`pnpm dlx supabase@3.0.0 db push --remote` from the repo root (the project must
be linked; ask René).

**Edit a diagram.** The diagrams in `docs/architecture.md` and
`docs/data-sources.md` are drawn in code: `docs/diagrams/*.py` place every box
and arrow by coordinate (shared helpers in `kit.py`). Each script holds the
English and Croatian text side by side (`t("English", "Hrvatski")`) and writes
`<name>.svg` and `<name>.hr.svg`. Change the script, then from `docs/diagrams/`
run `python3 <name>.py && node render.cjs` to regenerate the SVGs and PNGs
(needs `app/node_modules`). Check that the longer Croatian labels still fit, and
commit the script, SVGs and PNGs.

**Update the docs.** Documentation exists in English (`README.md`, `docs/*.md`)
and Croatian (`README.hr.md`, `docs/hr/*.md`). When you change one, change the other.

**Deploy.** Merge to `main`: Vercel deploys automatically. Then push any new
migrations and run the end-to-end tests against the live URL.

## 12. Gotchas

- **Node ≥ 20** (we use 22). On Node 18 Tailwind fails with `ERR_REQUIRE_ESM`.
  Without a system upgrade: `npx -y -p node@22 -p pnpm@9 -c 'pnpm dev'`.
- **Don't run `pnpm build` while `pnpm dev` is running**: both use `app/.next`
  and break each other.
- **Links in emails** are built from the request's address. Locally that is
  `http://localhost:3000`, so a doctor link opened on a phone fails;
  replace `localhost` with the computer's LAN address. Not an issue on Vercel.
- **Rate limits during heavy local testing**: clear them with
  `delete from rate_limits;` in Supabase Studio (local only).
- **Demo mode is per browser** (cookie). The doctor's browser needs `?demo=1`
  too for the uputnica-reading fallback.
- **Vercel previews** fail for commits by people who are not members of the
  Vercel project. Merge commits made by a member deploy fine.
- **Local vs hosted database**: the Supabase CLI targets the local database
  unless you pass `--remote`. `db reset --remote` wipes production; use
  `db push --remote` for new migrations.
